今天跟着“1024程序员节”的课表开始学 Python。上午的进度虽然只推进了两节（复习基础语法 + 函数）为了防止自己“学了就忘”，我把上午的踩坑记录和知识理解整理了一下。

一、 被 while 和 break 折磨

今天写的第一个完整程序是“重启终端：口令 1024。代码虽然不长，但我调了好几次。

最后那句可以不写的,就是看起来更美观一点

给自己记下的两个教训：

  1. check_count = 0 必须写在 while 外面！ 我今天才彻底搞懂，如果把这个记分牌写在 while 里面，每次循环一开始，分数就被强行清零了，永远也攒不够 3 次。
  2. 不加 break 就是无尽折磨。 while True 是个无底洞，如果我不写 break 去结束它，即使输入了 exit ，程序也会继续问我“请输入今日学习内容”。

二、 懂了，但没完全懂的函数（参数和返回值）

脑补：print 和 return 到底差在哪？
这是上午最卡我的地方。我还以为写个函数让它打印出来就完事了，今天才明白：

  • return 是交还结果：函数算完账，用 return 把数据悄悄塞回给外面的变量（my_exp），这一步在屏幕上是看不见的。
  • print 只是让你看个响：外面拿到了 my_exp 这个数据后，我再写个 print，屏幕上才会出现“获得经验值”。
  • 总结 ：没 return，外面的程序就接不到数据；没 print，我就看不到结果。

运行时我的翻车操作：
1. 输入空回车会死机 ：我运行测试的时候手欠，直接按了回车，结果报错，具体它写的什么不记得，但是大概意思就是：int( ) 遇到空字符串（空气）直接罢工了。以后测试这种题，千万不能习惯性乱按回车。
2. 不要乱加提示语：平时习惯写 input(“请输入…”)，但是系统是个瞎子😂，它只认纯数字。
3. 逻辑差点写反：差值是 1024 - 得分。如果超额完成，这个差值就是负数。所以判断是否输出 0，条件是 if diff <= 0 或者像上面那样 if diff > 0 走正常流程。看别人代码时，发现有人写成了 if diff >= 1024，逻辑直接就绕进去了。

四、数据结构：把数据管起来（列表与字典）

下午学了字典（Dict）和列表（List）

  • 字典：用大括号 { } 包起来，左边是键（Key），右边是值（Value）。
  • 我犯的错：一开始把年龄写成了 ‘year’ : ‘19’（加了引号变成了字符串）。以后要是拿年龄做加减法计算，绝对会报错，数字千万别加引号。

看着这三段代码，最大的感受就是“逻辑其实不难，就是把生活搬进代码里”。字典就是我的身份档案，函数就是我的展示卡片动作，while 循环就是我在等你跟我说话。

讲讲 while True 的感觉。就是可以比喻说：“这就好比我开了一家店，只要顾客没喊 exit（关门），我就一直坐在这里等他们输入指令。”

列表（简洁了一点）：

在代码分解1里面，最后一个代码后面，加上 'skills': ['Python', '写代码', '找Bug']。在“代码分解2”里面倒数第二行，加上 print(f"技能:{info_dict['skills']}")。
理解 ：为什么要在字典里塞一个列表？

  • 在写“个人信息卡片”的时候，我发现“爱好”通常只有一个（比如敲代码），用字符串就够了。但是“技能”往往有多个。
  • 如果我把技能写成 ‘skills’: ‘Python, 写代码, 找Bug’，它本质上还是一个长字符串，以后如果我想单独把 Python 挑出来，就很麻烦。
  • 所以我用了一个列表 [‘Python’, ‘写代码’, ‘找Bug’] 作为字典的值。这就是今天学到的（字典套列表）。当程序打印 info_dict[‘skills’] 的时候，它会原封不动地把整个列表展示出来。这样写，方便以后随时添加新技能。
